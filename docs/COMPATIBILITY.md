# Compatibility with ShinyProxy 3.2.4 (Java)

This rewrite is contract preserving: the same `application.yml`, the same HTTP routes, the same JSON
payloads, the same container environment/labels and the same browser assets. This page records every
*known deviation*, so that operators can judge the impact before switching.

Status legend: ✅ verified against the Java implementation · 🟨 implemented, verification pending ·
⬜ not implemented yet (see [PROGRESS.md](PROGRESS.md))

## Configuration

| Topic | Behaviour | Status |
| --- | --- | --- |
| Property names | Relaxed matching (`port-range-start` = `portRangeStart` = `PORT_RANGE_START`) | ✅ |
| Sources & precedence | CLI `--key=value` > environment > `application-{profile}.yml` > `application.yml` > defaults | ✅ |
| Configuration discovery | `application.yml`/`application.yaml` in the working directory, `--spring.config.location` (file, directory or comma separated list), `SPRING_CONFIG_LOCATION`; demo profile when nothing is found | ✅ |
| Lists | Single value, comma separated string, YAML list and indexed environment variables (`PROXY_ADMIN_GROUPS_0`) | ✅ |
| Placeholders | `${VAR}` / `${property:default}` resolved against environment and configuration; **unresolvable placeholders are left untouched**, matching Spring's `Environment` (required for Thymeleaf snippets in `parameters.template`) | ✅ |

| Nested environment binding | Only one array level is bound from the environment (`PROXY_SPECS_0_CONTAINER_IMAGE`); deeper nesting such as `PROXY_USAGE_STATS_0_ATTRIBUTES_0_NAME` must be configured in the file | 🟨 deviation, no known usage |

### Instance id (`SHINYPROXY_INSTANCE`)

The instance id is the SHA-1 of the configuration file rendered as canonical YAML (sorted keys), exactly
like `eu.openanalytics.containerproxy.util.Sha1#hash(Object)`. The canonical rendering is byte
compatible with Jackson's `YAMLMapper`, verified with golden fixtures
(`crates/containerproxy/tests/canonical_yaml.rs`) generated by the Java libraries:

```java
// reference program, run with jackson-databind + jackson-dataformat-yaml + snakeyaml on the classpath
ObjectMapper reader = new ObjectMapper(new YAMLFactory());
Object parsed = reader.readValue(new File(args[0]), Object.class);
String canonical = YAMLMapper.builder()
    .configure(SerializationFeature.ORDER_MAP_ENTRIES_BY_KEYS, true)
    .configure(MapperFeature.SORT_PROPERTIES_ALPHABETICALLY, true)
    .build()
    .writeValueAsString(parsed);
System.out.println(sha1Hex(canonical));
```

Verified values: the demo configuration hashes to `fa8f0913d4309dbe1fe44411fc59f5c6d6937837` in both
implementations, and a fixture covering escaping/unicode/empty collections/nested sequences hashes to
`68594e0ccaeb8b4db199920f58fb595f68641fc4`.

Known deviations:

* Configurations that use YAML 1.1 scalars (`yes`/`no`/`on`/`off` as booleans, octal `017`, hex `0x1F`,
  digit grouping `1_000`) are parsed with YAML 1.2 rules here, so their instance id differs from the
  Java one. The id is only used for asset URLs, container labels (app recovery) and the
  high-availability "outdated instance" check, so the impact is limited to migrating with running apps.
* When no configuration file exists (demo mode), the id is `unknown-instance-id`, as in Java.

## Expressions (`#{...}`)

The `spel` crate implements the subset of the Spring Expression Language that ShinyProxy
configurations use. It is cross-validated against the real Spring implementation:

```
tools/spel-crossvalidate/run.sh   # downloads spring-expression, evaluates the corpus, diffs the results
```

The corpus (`crates/spel/tests/corpus.rs`, 116 expressions taken from the ShinyProxy documentation and
configuration examples) produces **identical results in both implementations**, except for two
constructs where this implementation is deliberately more permissive:

| Construct | Spring | Here |
| --- | --- | --- |
| `map.key` (dot access on a `Map`) | fails (`MapAccessor` is not registered by default), `map['key']` is required | works, `map['key']` also works |
| `array.size()` (result of `String.split`) | fails (arrays have `length`) | works, `length` also works |

Supported: literals, arithmetic and string concatenation, property navigation with safe navigation,
indexing, method calls on strings/lists/maps/context objects, the `SpecExpressionContext` helpers
(`toList`, `toLowerCaseList`, `isOneOf`, `isOneOfIgnoreCase`), comparisons (incl. `matches` with Java's
full-match semantics and the textual `eq`/`ne`/`lt`/`gt` operators), logical operators, ternary and
elvis operators, inline lists/maps, projection `.![...]` and selection `.?[...]`.

Not supported (each produces an error naming the construct, at configuration load time):
constructor calls (`new ...`), bean method calls other than the registered beans, arbitrary static java
types. Allow-listed static types: `java.lang.System.getenv`, `java.lang.String.valueOf/join`,
`java.lang.Math.min/max/abs`, `java.lang.Integer.parseInt`, `java.lang.Long.parseLong`,
`java.lang.Boolean.parseBoolean`.

## Runtime

| Topic | Behaviour | Status |
| --- | --- | --- |
| Startup warnings | Same wording as Java for HA/session/recovery/cookie/spec-detail misconfigurations | ✅ |
| Fatal configurations | `store-mode: Redis` + app recovery aborts startup | ✅ |
| Panics | A panic inside a request or task does not terminate the server (`panic = "unwind"`), matching the Java thread-per-request behaviour | 🟨 |
